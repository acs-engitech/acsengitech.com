# Positions + Applications + Partners — implementation report

## Scope delivered

### 1. Database (Neon) — `api/_store.js`
- Added `acs_applications` and `acs_partners` tables (created in `init()`, `IF NOT EXISTS`).
- Added store functions: `insertApplication`, `listApplications`, `updateApplication`, `deleteApplications` and the partner equivalents.
- Added `getPositionTypes`/`setPositionTypes` and `getPartnerCategories`/`setPartnerCategories` using the existing JSONB blob pattern (keys `positionTypes`, `partnerCategories`), with the specified defaults.
- `getAll()` now returns `positions`, `positionTypes`, `applications`, `partners`, `partnerCategories` alongside the existing shape. `saveAll()` accepts the new keys.
- **Migration**: `getPositions()` reads the `positions` blob; if empty, it derives positions from the legacy `jobs` blob (`type: 'Full-time'` default, `tags: []`, status remapped `open|paused → live`, `closed → closed`) and persists that as the new `positions` blob. The `jobs` blob is left untouched for rollback.

### 2. Public endpoints
- `api/apply.js` (new) — multipart POST via `busboy` (`lib/uploads.js`), validates required fields + email format, uploads resume to Vercel Blob (`applications/<uuid>-<name>`, PDF/DOC/DOCX, 5MB max), inserts a row, rate-limited to 5/hour/IP (`lib/rate-limit.js`, in-memory).
- `api/partner.js` (new) — same pattern; optional profile file (PDF/DOC/DOCX/ZIP, 10MB max, `partners/<uuid>-<name>`), portfolio URLs parsed from JSON array or comma/newline text.
- Both skip Blob upload and log a warning + return a `/uploads/...` stub URL when `BLOB_READ_WRITE_TOKEN` is unset (local dev).

### 3. Admin endpoint — `api/admin.js`
- `GET` returns the extended `getAll()` shape (positions, positionTypes, applications, partners, partnerCategories) plus `analytics`.
- `POST` handles the existing blob-save payload AND a new `{action, ...}` shape: `application.update`, `application.delete`, `partner.update`, `partner.delete`. Row actions return the refreshed `getAll()` shape.
- Fixed a latent mock-ability bug: `getAll`/`saveAll`/`getAnalytics` were destructured at module load (captured the reference once, un-mockable across tests); switched to `store.getAll()` etc. so tests can substitute store methods per-test. Applied the same fix to `api/public.js`.

### 4. Public forms
- `career.html` — replaced the FormSubmit-based `<form>` with a same-styled form (`.acs-apply-form` classes preserved) that: loads live positions into a `<select>` from `/api/public`, submits via `fetch('/api/apply', {method:'POST', body: new FormData(form)})`, shows inline loading/success/error state, and resets on success.
- `acs-runtime.js` — "Apply Now" now calls `window.acsSelectPosition(id)` (scrolls to `#acs-job-form`, pre-selects the position, focuses the name field) instead of a `mailto:` link; falls back to `mailto:` if the form script hasn't loaded.
- `partner-with-us.html` (new) — standalone page reusing the `.acs-apply-form` visual language (navy #1C3A62, Inter/Heebo, rounded cards) with category select (from `/api/public`), contact fields, a dynamic portfolio-URL list ("+ Add another"), optional profile upload, and inline submit feedback via `/api/partner`.
  - **Simplification**: built a lightweight, on-brand header/footer rather than replicating the ~1200-line legacy WordPress/Elementor export used by the scraped static pages — that markup is page-specific cruft, not a reusable include. Flag if exact WP chrome parity is required; easy to layer in later.
- `api/public.js` — now returns `positions` (live only), `positionTypes`, `partnerCategories`, and keeps `jobs` populated from positions for legacy consumers.

### 5. Admin UI — `admin-src/index.html`
- Sidebar: `careers` renamed to `positions` (label "Positions", helper "Open roles & internships"); added `applications` and `partners` nav buttons with inline SVG icons matching the existing style.
- Careers panel renamed to Positions panel (`id="positions"`) with: Manage-types button, "View careers page" link, New position button; role editor gained a Type select (from positionTypes, with "+ Manage types" link) and a Tags input rendering chips; status is now a live/closed radio group.
- New Applications panel: workflow filter chips (all/new/reviewed/shortlisted/rejected with live counts), position/date-range/search filters, bulk select + delete, per-row resume link, inline status select, Details button, Delete button.
- New Partners panel: same pattern with category filter instead of position filter, portfolio links, profile file link.
- Both panels have a slide-in right drawer (`#applicationDrawer`, `#partnerDrawer`) with full record details + notes textarea + Save.
- Shared type/category manager modal (`#typeManagerModal`) for CRUD on `positionTypes` / `partnerCategories`.
- `admin-src/css/style.css` — added drawer, modal, entity-row, and filter-row styles (all Tailwind `@apply`-based, consistent with the existing design tokens).

### 6. Admin JS — `admin-src/js/admin-app.js`
- Extended state with `positions`, `positionTypes`, `applications`, `applicationFilters`, `applicationSelectedIds`, `selectedApplication`, and the partner equivalents.
- Added `renderPositions`, `renderApplications`, `renderPartners`, `renderTypeManager`, filter/bulk/drawer handlers, and an `apiAction(action, body)` helper that POSTs `{action, ...}` to `/api/admin` and re-renders from the response.
- CSV export for both lists (client-side Blob download).
- `render()` now calls all new render functions; `load()`/`save()` centralized into `applyData()` so every response shape (GET, POST-save, POST-action) updates the same state fields consistently.

### 7. Vercel Blob
- `npm install @vercel/blob busboy` (dependencies). `uuid` was considered but dropped — `crypto.randomUUID()` (Node stdlib) already covers unique filenames, no need for the extra dependency.
- `admin-src/README.md` — added a "Required environment variables" section documenting `DATABASE_URL`, `BLOB_READ_WRITE_TOKEN` (enable Vercel Blob storage on the project; token is auto-injected), `ACS_ADMIN_EMAIL` / `ACS_ADMIN_PASSWORD_HASH`.

### 8. Local dev server
- `local-dev-server.js` — added `/api/apply` and `/api/partner` routes. No other change needed: the existing static-file fallback (`fullPath + '.html'`) already serves `partner-with-us.html` at `/partner-with-us`, and the plain `http.IncomingMessage` req is pipeable straight into busboy.

### 9. Migration & compatibility
- Handled in `_store.js.getPositions()` as described above (auto-migrates on first read, idempotent).
- `/api/public` returns both `positions` and a `jobs` view derived from them for old consumers.
- `acs-runtime.js`'s `renderCareers`/`careerDetailsHtml` already consume `data.jobs`, which now reflects `positions` first (via `/api/public`'s mapping) with the original `DEFAULT_JOBS` fallback intact when the DB is unreachable.

## Environment variables the user must set (Vercel project settings)
- `DATABASE_URL` — Neon Postgres connection string (already required by the existing admin).
- `BLOB_READ_WRITE_TOKEN` — enable **Vercel Blob** storage on the project (Storage tab); Vercel injects this automatically once enabled. Without it, uploads fall back to a local `/uploads/...` stub (dev-only, logs a warning).
- `ACS_ADMIN_EMAIL` / `ACS_ADMIN_PASSWORD_HASH` — unchanged, already documented.

## Known simplifications (ponytail-flagged, easy to extend)
- Rate limiting is a single in-memory bucket per serverless instance (`lib/rate-limit.js`) — resets on cold start and isn't shared across instances. Fine at current submission volume; swap for a shared store (Redis/Neon table) if abuse becomes real.
- `partner-with-us.html` uses a lightweight custom header/footer instead of replicating the full legacy WordPress/Elementor chrome baked into the scraped static pages.
